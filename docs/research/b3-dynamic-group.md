# B3 的「动态分组」条件设计

> 目标：为 **B3 战法**设计可用的同花顺动态分组语句。
> 所有覆盖率/准确率数字均为**本仓库真实数据实测**（500 只标的、日线），不是推测。
> **重要前提**：动态分组是"与"（AND）逻辑，每加一个条件都会砍掉一批结果。
> 因此本报告的核心是**权衡**：覆盖率（能否捞到真 B3）vs 准确率（选出的票里多少真是 B3）。

## 0. 先说结论

1. **最容易犯的错**：用「连续阴线 → 今日收阳」的反包语义去找 B3。
   **实测交集 = 0**——B3 当天，前 3 日连阴的情况是 **0 / 252 次**。
   因为 B3 与"反包"是**语义相反**的两种形态（见第 1 节）。那个语义对应的是 B1/砖型图反包。

2. **B3 的可表达核心是「平开 + 小实体」**（十字星/小阴线）——
   实测 B3 当天 **100%** 满足这两条。这是最可靠的锚。

3. **但只写这两条会有十几万个结果**（准确率仅 0.16%），必须叠加"前面刚涨过"这个前提。
   加「近 3 日内有过 ≥4% 大涨」后，**覆盖率 82.9%、准确率提升到 1.46%（提升 934 倍）**。

4. **不要加「量在 10 日线上」**：它把覆盖率从 82.9% 砍到 **22.2%**。
   B3 当天多为**缩量歇整**（反向条件「缩量」反而覆盖 60.7%、准确率更高达 1.83%）。

5. **动态分组永远无法精确复现 B3**——因为 B3 的完整定义含 **J 值 < 55**、**放量**、
   以及 **B1→B2→B3 的链条依赖**，这些都是自定义量。**这是上限问题，不是写法问题。**

## 1. B3 的真实定义

来自本仓库 `src/aqlab/rules_zgnb.py` 的 `B3Confirm`：

| 条件 | 具体规则 |
| --- | --- |
| **前提** | 最近 **2 天**内出现过 **B2** 信号 |
| **B2 的定义** | B1 后 3 日内涨幅 ≥ 4%，且 **J < 55**，且**放量** |
| **B1 的定义** | 超跌（J ≤ 13、缩量、双线等一组硬/软条件） |
| **今日 K 线** | **平开**：`|open / prev_close - 1| ≤ 1%` |
| | **十字星或小阴线**：`|close - open| / prev_close ≤ 2%` |

### 1.1 语义链（这是理解 B3 的关键）

```
B1 超跌        →   B2 放量上攻（涨≥4%）   →   B3 平开+小实体（歇一口气）
（跌透了）         （资金进场拉起来）          （涨完后横住/小回，蓄势）
```

**B3 是"上涨之后的中继休整"，不是"下跌之后的反弹"。**
这就是为什么用"连阴→收阳"去找它必然落空——**方向完全相反**。

## 2. B3 长什么样（实测特征分布）

500 只标的、**252 个真实 B3 信号**，各可观测特征的满足率：

| 特征 | B3 中满足数 | 占比 |
| --- | ---: | ---: |
| **平开**（`|open/prev_close-1| ≤ 1%`） | 252 / 252 | **100.0%** |
| **小实体**（`|close-open|/prev_close ≤ 2%`） | 252 / 252 | **100.0%** |
| 近 3 日内有过 ≥4% 大涨 | 209 / 252 | **82.9%** |
| 股价在 20 日线上 | 174 / 252 | 69.0% |
| 量在 10 日线上 | 71 / 252 | **28.2%** |
| **前 3 日连阴** | **0 / 252** | **0.0%** |

**读法**：
- 前两行是定义本身，所以必然 100%；
- **「近 3 日大涨」82.9%** —— 这是**可以拿来当过滤条件的最强特征**；
- **「量在 10 日线上」只有 28.2%** —— 说明 **B3 当天大多不满足量能条件**，
  你把它写进语句，等于**主动排除掉 71.8% 的真 B3**；
- **「前 3 日连阴」0%** —— 直接证实反包语义与 B3 不相交。

## 3. 实测：各候选语句的覆盖率与准确率

| 候选语句 | 选出数 | 覆盖 B3 | 准确率 | 提升倍数 |
| --- | ---: | ---: | ---: | ---: |
| A 平开 + 小实体（纯形态） | 161,700 | 100.0% | 0.16% | 1.0x |
| **B A + 近 3 日大涨 4%** | 14,357 | **82.9%** | **1.46%** | **934x** |
| C B + 20 日线上 | 10,273 | 59.5% | 1.46% | 937x |
| D B + **量在 10 日线上**（可避免） | 5,798 | **22.2%** | 0.97% | 620x |
| E B + 前期超跌（20 日内跌 >15%） | 667 | **0.0%** | 0.00% | — |
| F E + 20 日线上 | 34 | 0.0% | 0.00% | — |
| G B + **缩量**（量 < 10 日均量） | 8,352 | **60.7%** | **1.83%** | **1176x** |
| **H B + 20 日线上 + 缩量** | 5,281 | 40.1% | **1.91%** | **1227x** |

**几个关键读数**：

1. **B 是最佳"宽口径"**：只用「平开+小实体+近3日大涨4%」，能捞到 **82.9%** 的真 B3；
2. **D（你的量能条件）是明显的错误选择**：覆盖率从 82.9% 跌到 **22.2%**，
   而且准确率**还下降了**（1.46% → 0.97%）——**既漏又不准**；
3. **G/H（缩量）反而更好**：准确率 1.83% / 1.91%，**比放量条件高近一倍**。
   这颠覆直觉，但符合 B3 语义——"涨完之后**缩量**横住"才是蓄势；
4. **E/F（要求前期超跌）覆盖率归零**：又一次证明 B3 **与超跌无关**，
   它要求的是"**已经涨过**"，不是"跌透了"。

## 4. 推荐语句

### 4.1 首选（宽口径，先看结果）

```
平开，小实体，近3日涨幅超过4%的股票
```

**对应实测 B**：覆盖率 82.9%。
配套可拆成动态分组能理解的说法（若上一句被拒，改这组）：

```
今天开盘价和前收盘价相差不到1%，今天涨跌幅在2%以内，最近3天有过涨幅超过4%的股票
```

### 4.2 加均线（对齐 Z 哥"白线/黄线之上"）

```
平开，小实体，近3日涨幅超过4%，股价在20日线上的股票
```

**对应实测 C**：覆盖率 59.5%。

### 4.3 若结果太多，用"缩量"而不是"放量"

```
平开，小实体，近3日涨幅超过4%，股价在20日线上，今天成交量小于10日均量的股票
```

**对应实测 H**：覆盖率 40.1%，**准确率最高（1.91%）**。

> **注意措辞方向**：是**「小于」10 日均量**（缩量），不是"大于"。
> 这是本报告最反直觉、但数据支持最强的一条建议。

### 4.4 中文完整版（备用表述）

```
今天平开（开盘价与前收盘价之差不超过1%），今天是小实体（收盘与开盘之差不超过2%），
最近3个交易日内出现过涨幅超过4%的大阳线，股价在20日均线之上，非ST的沪深A股
```

## 5. 三个必须避免的写法

| ❌ 避免 | 原因（实测） |
| --- | --- |
| **前 3 日连阴 + 今日收阳** | 与 B3 **交集为 0**；那是 B1/砖型图反包的语义 |
| **成交量在 10 日线上** | 覆盖率 82.9% → **22.2%**，且准确率**下降**（1.46% → 0.97%） |
| **要求前期超跌/大跌** | 覆盖率直接归零（E/F 均为 0.0%）——B3 要求"已涨过" |

**一句话记忆**：**B3 是"涨过之后歇一口气"，不是"跌完之后反包"。**

## 6. 无法表达的部分

以下三条是 B3 定义的组成部分，但**动态分组无法表达**，因此**不存在**能 100% 复现 B3 的语句：

| 无法表达 | 说明 |
| --- | --- |
| **J 值 < 55** | KDJ 的 J 值，需指标计算 |
| **放量**（B2 的前提之一） | 可用"某个量比条件"近似，但不等价 |
| **B1 → B2 → B3 链条依赖** | 需要先识别 B1（一组超跌条件），再识别 B2，动态分组做不到链式判断 |

**所以准确率最高只有 ~1.9%**——这不是写法问题，而是"用 4 个可表达条件去逼近
一个含 3 个不可表达条件的信号"的必然结果。

**实用建议**：把动态分组当**粗筛**（82.9% 覆盖），
再用本仓库的 `aqlab` 做**精筛**（它在本地能算出完整 B3）：

```bash
# 动态分组粗筛出票 -> 用本仓库精确判定 B3
python -m aqlab.cli screen --symbols <票池> --days 500 ...
```

## 7. 怎么验证

不要只看"选出的票像不像"。用**重叠率**验证：

1. **准备对照集**：从 `picks_archive` 找有 B3 记录的日期，或直接用本仓库跑全市场得到 B3 名单：
   ```bash
   python -m aqlab.cli universe-study --daily-dir data/universe/daily --rule b3_confirm ...
   ```
2. **把动态分组选出的票**与本地 B3 名单比对：
   - **覆盖率** = 本地 B3 里有多少被动态分组捞到 → 期望 **> 80%**
   - **准确率** = 动态分组选出的票里有多少真是 B3 → 期望 **~1.5%**
3. **若覆盖率远低于 80%**，说明某条附加条件过紧（最可能是量能）。

### 7.1 我的验证脚本（可复现）

本报告所有数字来自这一段逻辑（可自行重跑）：

```python
# 真实 B3 信号
sig = B3Confirm().signal(df)
# 候选条件（对应上表 B / C / G / H）
shape = (abs(open/prev_close - 1) <= 0.01) & (abs(close-open)/prev_close <= 0.02)
surge = (close/prev_close - 1 >= 0.04).rolling(3, min_periods=1).max().shift(1)
cand_B = shape & surge
cand_H = cand_B & (close > ma20) & (volume < volume.rolling(10).mean())
# 覆盖率 / 准确率
cover = (cand & sig).sum() / sig.sum()
precis = (cand & sig).sum() / cand.sum()
```
